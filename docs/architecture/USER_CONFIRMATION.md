# 사용자 확인 흐름

`egov_scaffold_project` 와 `egov_add_entity` 는 사용자가 정해야 하는 인자가 생략되면 사용자에게 직접 묻습니다. 이 문서는 그 흐름의 구조와 응답별 처리를 설명합니다.

## 배경

사용자는 보통 "다음 DDL 로 프로젝트를 만들어 줘"처럼 요청하고, 표준프레임워크의 버전이나 첨부파일 포함 여부를 말하지 않습니다. 이 값들은 산출물을 크게 바꿉니다. 버전에 따라 Java 와 Spring 의 버전이 달라지고, 첨부파일을 포함하면 업로드와 다운로드 경로, DB 테이블이 추가됩니다. 그래서 AI 가 임의로 정하거나 서버가 기본값으로 채우지 않고, 사용자의 선택을 받도록 했습니다.

확인의 대상은 다음 세 가지입니다.

| 도구 | 인자 | 질문의 내용 |
|------|------|-------------|
| `egov_scaffold_project` | `stackVersion` (그리고 `projectType`) | 5.1 Boot, 4.3 Boot, 4.3 WAR 가운데 어느 것으로 만들지 |
| `egov_scaffold_project` | `withAttachment` | 프로젝트에 표준 첨부파일 기능을 포함할지 |
| `egov_add_entity` | `withAttachment` | 엔티티에 표준 첨부파일 기능을 연결할지 |

## 두 가지 경로

```text
인자가 생략됨
   │
   ├─ 클라이언트가 Elicitation 을 지원함
   │     1. 서버가 질문 화면을 띄움
   │     2. 사용자가 답함
   │     3. 서버가 그 값으로 생성
   │
   └─ 지원하지 않음 (또는 60초 안에 답이 없음)
         1. 서버가 파일을 만들지 않고 오류를 반환
         2. AI 가 사용자에게 물음
         3. AI 가 인자를 채워서 다시 호출
         4. 서버가 생성
```

1. **MCP Elicitation**: 서버가 `elicitation/create` 요청으로 클라이언트에 질문 화면을 띄웁니다. 사용자가 고른 값이 서버로 돌아오고, 서버는 그 값으로 생성을 계속합니다.
2. **AI 를 통한 확인**: 클라이언트가 Elicitation 을 지원하지 않으면, 서버는 파일을 만들지 않고 `isError` 로 응답합니다. 응답의 문구에는 사용자에게 무엇을 물어야 하는지, 어떤 인자를 어떤 값으로 지정해서 다시 호출해야 하는지가 들어 있습니다.

어느 경로에서든 사용자의 선택 없이 파일이 만들어지지 않습니다.

AI 가 인자를 임의로 채우지 않도록, 도구의 인자 설명(`.describe()`)에는 "사용자가 요청에서 밝히지 않았다면 이 인자를 생략하세요. 임의로 채우면 안 됩니다"라는 안내가 들어 있습니다.

## 구현 위치

| 파일 | 역할 |
|------|------|
| `src/index.ts` | 도구 핸들러에서 사용자 확인을 수행한 뒤, 정해진 값으로 도구 함수를 호출 |
| `src/utils/scaffold/elicitForm.ts` | Elicitation 요청을 보내고 응답을 정리하는 공용 모듈 |
| `src/utils/scaffold/scaffoldDecision.ts` | `egov_scaffold_project` 의 질문 순서와 응답 처리 |
| `src/utils/scaffold/attachmentDecision.ts` | `egov_add_entity` 의 질문과 응답 처리 |

사용자 확인을 도구 함수(`src/tools/`)가 아니라 핸들러(`src/index.ts`)에서 수행하는 이유는, 도구 함수의 입력 계약을 단순하게 유지하기 위해서입니다. 도구 함수는 `withAttachment` 의 기본값을 `false` 로 두고 질문을 하지 않으므로, 테스트에서 MCP 연결 없이 직접 호출할 수 있습니다.

핸들러는 입력이 2차 검증을 통과하지 못하면 질문하지 않고 검증 오류를 바로 돌려줍니다. 잘못된 입력에 대해 사용자가 먼저 질문에 답하게 되는 일을 막기 위해서입니다.

### 요청의 형태

`elicitForm` 은 `mode: "form"` 으로 요청하고, 질문 항목을 JSON Schema 로 전달합니다. 항목은 boolean 과 단일 선택(`oneOf`)의 두 종류이며 모두 필수입니다. 응답을 기다리는 시간은 질문 하나에 60초입니다.

Elicitation 을 지원하지 않는 클라이언트에는 MCP SDK 가 요청을 보내기 전에 예외를 던집니다. `elicitForm` 은 이 예외와 시간 초과, 그 밖의 호출 오류를 모두 "질문할 수 없음"으로 처리해서, 호출하는 쪽이 AI 를 통한 확인 경로로 넘길 수 있게 합니다.

## egov_scaffold_project 의 질문

### 선택지

| 값 | 화면에 보이는 이름 |
|----|--------------------|
| `boot-5.1` | 표준프레임워크 5.1 (Spring Boot 3, Java 17) |
| `boot-4.3` | 표준프레임워크 4.3 (Spring Boot 2.7, Java 8) |
| `war-4.3` | 표준프레임워크 4.3 WAR (Spring 5.3, Java 8, JSP + Tomcat) |

`war-4.3` 선택지는 `projectType` 이 생략되었고 `withAttachment` 가 `true` 가 아닐 때만 보입니다. WAR 는 첨부파일을 지원하지 않기 때문입니다.

### 질문의 순서

| 호출 형태 | 동작 |
|-----------|------|
| `projectType='war'` | 질문하지 않습니다. 버전은 4.3, 첨부파일은 포함하지 않는 것으로 정합니다. |
| `stackVersion` 과 `withAttachment` 를 모두 지정 | 질문하지 않습니다. |
| `stackVersion` 이 생략되었고 WAR 선택지가 보이는 경우 | 버전을 먼저 묻습니다. WAR 를 고르면 첨부파일 질문 없이 끝나고, Boot 를 골랐고 `withAttachment` 가 생략되었으면 첨부파일 포함 여부를 이어서 묻습니다. |
| `projectType='boot'` 이고 `stackVersion` 이 생략됨 | 생략된 항목을 하나의 질문 화면에 담아서 한 번에 묻습니다. |
| `stackVersion` 만 지정 | 첨부파일 포함 여부만 묻습니다. |
| `withAttachment=true` 이고 `projectType` 과 `stackVersion` 이 생략됨 | Boot 의 두 버전만 선택지로 보여 주고 버전을 묻습니다. |

질문의 문구는 묻는 항목에 따라 다음 가운데 하나입니다.

- "이 프로젝트의 표준프레임워크 버전과 표준 첨부파일 기능 포함 여부를 선택해 주세요."
- "이 프로젝트를 어떤 표준프레임워크 버전으로 생성할까요?"
- "이 프로젝트에 표준 첨부파일 기능을 포함할까요?"

### 응답별 처리

| 응답 | 버전을 묻는 질문 (버전과 첨부파일을 함께 묻는 질문 포함) | 첨부파일만 묻는 질문 |
|------|----------------------------------------------------------|----------------------|
| 수락(`accept`)과 유효한 값 | 그 값으로 생성 | 그 값으로 생성 |
| 거절(`decline`) | 생성하지 않음 | 첨부파일 없이 생성 |
| 취소(`cancel`) | 생성하지 않음 | 생성하지 않음 |
| 질문할 수 없음, 시간 초과, 값이 빠진 수락 | 생성하지 않고 오류를 반환 | 생성하지 않고 오류를 반환 |

거절의 처리가 질문에 따라 다른 이유는 다음과 같습니다. 첨부파일 질문의 거절은 "포함하지 않는다"는 답으로 볼 수 있지만, 버전 질문의 거절에는 대신 쓸 값이 없습니다.

사용자가 생성을 취소한 경우에는 오류가 아니라 정상 응답으로 "사용자가 취소하여 아무 파일도 생성하지 않았습니다."를 돌려줍니다. AI 가 이를 실패로 보고 다시 시도하지 않게 하기 위해서입니다.

하나의 질문 화면에서 일부 항목에만 유효한 값이 돌아오면, 답하지 못한 항목만 지정해서 다시 호출하라는 오류를 돌려줍니다.

## egov_add_entity 의 질문

판정의 순서는 다음과 같습니다.

1. `withAttachment` 가 지정되어 있으면 그 값을 쓰고 묻지 않습니다.
2. 대상 프로젝트가 Boot 가 아니거나 스택을 감지하지 못하면 묻지 않고 `false` 로 처리합니다. 스택을 감지하지 못한 경우의 오류는 도구 함수가 보고합니다.
3. 그 밖의 경우에는 사용자에게 묻습니다.

질문의 문구는 "엔티티 '<이름>'에 표준 첨부파일 기능을 연결할까요?"이며, 프로젝트에 첨부파일 인프라가 없으면 "프로젝트에 첨부파일 인프라가 없어 함께 설치됩니다."가 덧붙습니다. 인프라의 유무는 질문의 문구를 고르는 데에만 쓰고, 질문할지 여부에는 영향을 주지 않습니다.

응답별 처리는 위 표의 "첨부파일만 묻는 질문"과 같습니다.

## 오류 문구

질문할 수 없을 때 돌려주는 오류는 `[조치 후 재시도 가능]` 으로 시작하고, 사용자에게 물을 내용과 지정할 인자를 알려 줍니다.

```text
[조치 후 재시도 가능] 첨부파일 포함 여부를 사용자에게 확인하지 못해 아무 파일도 생성하지 않았습니다. 사용자에게 첨부파일 기능을 포함할지 물은 뒤 withAttachment 를 true 또는 false 로 지정해 나머지 인자는 그대로 다시 호출하세요.
```

`egov_scaffold_project` 에서 `projectType` 까지 생략된 채로 버전을 확인하지 못하면, `projectType` 과 `stackVersion` 을 함께 지정하라고 안내합니다.

## SDK v2 로의 전환

현재 구현은 `@modelcontextprotocol/sdk` 1.29 의 `elicitInput` 을 사용합니다. SDK v2 에서는 패키지와 호출 방식이 달라지며, 전환할 때 고쳐야 할 내용은 [MCP SDK v2 전환 가이드](../development/SDK_V2_MIGRATION.md)에 정리되어 있습니다.
